# Research status and acceptance criteria

The engineering framework implements both editing paths, upstream integrations, a bounded trained-rule round trip, generic transactions, architecture adapters and a budgeted agent controller. That does not complete the research objective of reliably improving arbitrary LLMs or outperforming the reference work.

## What has actually been established

- On the trained binary-majority checkpoint, component pruning keeps uniform token aggregation into an opaque MLP. Full-span replay of that component stage matches the native model on 512/512 length-9 answers. The full-path and QK engines match 386/512 and are rejected. Logit error stays near 5, so the claim is decision agreement under calibrated linear LayerNorm.
- The greedy driver on unique copy and sort preserves the first answer token more often than the rest of the answer. Direct QK weight matching leaves the remaining attention paths opaque. A separate 16-step coefficient pilot scores every answer position. It accepts copy's component stage on 144/144 final positions and rejects the later stages. Sort's linear LayerNorm engine starts at 95/96 and is rejected. Two low-FVU MLP fits are rejected because held-out decisions miss the frozen model. Details are in `docs/decompilation.md`.
- A finite behavioral library matches majority and copy on held-out strings. Sort agrees with the model on 92/96 calibration positions, below the 0.99 bar, so the native model stays in place. This is activation/behavior-informed synthesis, not weight-only discovery or a universal decompilation result.
- Editing that rule can generate a new model with Tracr, or patch the original model by solving a restricted rank-one write problem.
- The constrained compiler needs explicit activation probes. It uses an LP rather than gradient descent. Auxiliary rational inequality checking is not an IEEE float32 proof. Native execution is tested separately.
- Counterexamples matter: the initial patch fails on two length-9 inputs. Two refinement rounds satisfy that bounded oracle. One length-11 input still fails; final held-out accuracy is 2,047/2,048. These failures remain in the report.
- A real 134.5M-parameter language model supports numerical program editing, export/reload and undo. The smoke-test edit is not claimed to improve language quality.

## Public matched-arm measurement

`examples/public_comparison.py` scored three seeds and four development proposals per selective arm. Held-out and collateral rows were scored after selection. The upstream checkout was revision `787398b0f4393a90ad02cd8e71be48d1e85d2b21`. Checkpoint names are `bin_majority-@1l1h16d3lr01drop`, `unique_copy-@2l1h64d3lr01drop`, and `sort-@1l1h256d3lr01drop`. The first language rows are 16-token windows from the public-domain opening of Pride and Prejudice (passage sha256 `59b9b35994bdc1df809fdf02be72d208ba7fe0f5c865089f5a78031f0ef45d89`): 16 development windows, 16 held-out windows, and 8 collateral windows from the next chapter. Those language windows are repeated across seeds. The restored language fingerprint is `b424a1ed3130606acdc0cc58f02e7df4cbc6613dcaaa8730ba0e822307fe76c7` (81,912,576 parameters, GPT-2 family), taken from the undo package stored with the smoke edit. Exact rows are in `docs/results/public-baselines.json`. That file is kept.

`methods_better_than_untouched_on_every_seed` is empty for every task. A method is listed only when held-out accuracy is strictly higher and held-out NLL is strictly lower on every seed.

Majority held-out accuracy is 1.0 on all 16 examples for every arm and seed. Untouched held-out NLL is 0.0214, 0.0270, and 0.0236. The shared head-scale arms (scaling, direct, and program) lower it to 0.0052, 0.0053, and 0.0061. Direction lowers it to 0.0056, 0.0056, and 0.0065. Accuracy does not move. These are confidence changes on an already correct set, with Wilson intervals that still reach 1.0.

Sort does not produce a cross-seed winner. On seed 0, direction raises development accuracy from 0.970 to 0.985 and lowers held-out accuracy from 1.000 to 0.986. On seed 2, the head-scale arms keep held-out accuracy at 0.986 and raise held-out NLL from 0.0822 to 0.1351.

That is one 16-example fluctuation, not a language-quality result, and it is separate from the symbolic count-rule result of 2,047/2,048.

Direct, program, and scaling match on these runs because they apply one head-scale grid. That match is an interface control.

Held-out rows were not sent to the policy. The policy was the installed Grok CLI, one turn at a time, and the usage fields below are copied from `grok --output-format json`.

The retained checkpoint is the original model: 0 changed scalars, held-out accuracy 1.0, held-out NLL 0.02138, collateral accuracy 1.0. Selection forwards were 8 of 16. Wall time was 77.6 seconds.

## Weight-space programming baseline

The blog experiment has not been reproduced. The published logs pin the text part of `Qwen/Qwen3.5-0.8B` at revision `2fc06364715b967f1860aea9cf38778875588b17`, profile `qwen35think`, and prompt `v3`. Thinking is on. The user message is the problem, a newline, and "Please reason step by step, and put your final answer within \\boxed{}." Sampling is temperature 0.6, top_p 0.95, top_k 20, presence penalty 1.5, and at most 32,768 new tokens. The editor was `gpt-6-astra` through Codex with reasoning effort `max` and its own tools off. Evaluation was vLLM, and the last boxed answer was graded with math-verify. The authors' `eval/unedited/merged.json` records MATH-500 accuracy 0.079 and cut share 0.93, and GSM8K accuracy 0.138. The 50-pass edit `p50c` records MATH-500 0.481 and GSM8K 0.671. Those scores were not rerun here. A 25-problem file on the edited model card is a different artifact.

`examples/qwen35_blog_protocol.py` rebuilt every published diff from that checkpoint. `p10c` (30 tensors), `p25c` (1 tensor), and `p50c` (2 tensors, 130,188 changed bfloat16 entries) match the published base and edited sha256 values. The check took 2.18 seconds. The product install is still transformers 4.57.1 and still fails closed for `qwen3_5`. The load used an isolated transformers 5.17.0 process, the published `qwen3_5_text` config, and `Qwen3_5ForCausalLM` (752,393,024 parameters, bfloat16, CPU, 0.757 seconds). Vision weights were not loaded.

The same command then drew one sample of MATH-500 `test/precalculus/807.json` with a 96-token cap. That cap is an implementation check, not the 32,768-token protocol. The untouched sample produced 96 tokens in 94.326 seconds (1.0177 tokens/second), hit the cap, and had no closed boxed answer. The in-memory `p50c` edit then produced 96 different tokens in 146.838 seconds (0.6538 tokens/second), also with no boxed answer. A later run with the same problem, seed, and edit, and a 256-token cap, is in `docs/results/qwen35-blog-length256.json`. Untouched produced 256 tokens in 347.106 seconds (0.7375 tokens/second). `p50c` produced 256 tokens in 322.677 seconds (0.7934 tokens/second). Both hit the cap, both stayed inside an open think span, and neither fired `verbatim_loop_end` or the documented `repetitive_end` rule. The texts diverge. At the slower of these rates, one 32,768-token answer is still many hours. Transformers 5.17.0 has no `presence_penalty` argument, so the smoke subtracts 1.5 from logits of tokens already present in the generated span and then applies temperature, top-k, and top-p. `causal_conv1d` and `flash-linear-attention` were absent, so the reference PyTorch kernels ran. No Grok editing call was made. `verbatim_loop_end` matches `mathqa.loop_signals`. `repetitive_end` follows that docstring because `mcqa.loop_signals` is not in the public release. The blog cut share counts a `length` finish at 32,768 tokens, which these caps do not measure.

## What remains open

The session loop can score a copy or sort answer across every target token, and it rejects a row whose labels stop early. The paper HTCondor schedule, the longer MLP primitive set, logit-level equivalence, sequence-wide copy and sort edits, and a statistically supported improvement over matched strong agents remain open. The 16-step coefficient pilot is a separate measured limit, not that schedule. The live Grok pilot is still the one rejected majority rule. Qwen3.5 and other hybrid decoders stay unsupported in the product runtime. Unknown QK paths stay opaque. Do not use final evaluation failures for refinement.

The blog's Qwen math result is not a result of this repository. The bit-exact edit check and the 96- and 256-token smokes do not reproduce the published MATH-500 or GSM8K numbers, and a tool-interface pilot must not be reported as a defeat of that result. A full untouched score still needs the published vLLM sampler, the 32,768-token budget, four MATH-500 samples, and two GSM8K samples. The research-compiler bridge is a separate unintegrated worker. Its trained majority run stayed `tracr_lowerable` false. A new Tracr model is not a patch of the source checkpoint. Task lookup and an LP or output-layer fit are not decompilation.
